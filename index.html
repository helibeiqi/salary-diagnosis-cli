薪酬诊断工具

salary-diagnosis-cli —— 本地优先、模型不碰计算、默认脱敏的薪酬诊断 CLI
源自真实薪酬场景 Python · 30 个模块 MIT 开源 · 28 次提交 合成数据全链可复现

让大模型负责听懂人话、串起流程、把结果讲成人话；
所有跟钱有关的计算，一律交给一段确定性程序去算。

三十秒：凭什么敢用

模型不碰数字 它只返回「调哪个函数、传什么参数」，11 个工具确定性执行。结果可复现、可审计——错也能查得出来。
数据默认不出门 默认本地模型运行，本地不可用时只报错、不回退云端；一键脱敏；绝不打印真实明细；产物落盘不进模型上下文。
口径只写在一处 业务常量集中管理，沙箱与主路径共用同一执行入口。改一版不会对不上上一版，不会出现「偶尔不对」。

它解决的三件麻烦事

排调薪方案时改一版大半天；通用大模型给的方案总额超预算，而且错得很有道理、查不出来。
谁在带宽哪一段、谁该调、调多少、全年加薪会不会超——只看得见一张底表，看不见结构。
口径会漂：市场数据取哪个来源、按中位还是高位对标，人手工整都会漂，何况 AI 每次重新理解一遍。

跑出来的样子

数字是可以当场复算的

下面是内置合成样例数据（150 条，与任何真实自然人无关）跑出的结果，任何人跑同一条命令都会得到同一组数字：

输出项结果
红圈（薪酬偏高）31 人 · 20.67%
绿圈（薪酬偏低）26 人 · 17.33%
带宽内合理93 人 · 62.00%
预算 5% 对应总额1,958,520 元
优先补绿圈：第一步补差成本472,889 元 / 26 人

这组数字同时是 CI 里的金标准对账用例——口径一改，测试立刻失败。这也是「可审计」的具体含义。

三条命令跑通（不需要任何大模型）

git clone https://github.com/helibeiqi/salary-diagnosis-cli.git
cd salary-diagnosis-cli && pip install -r requirements.txt
python run_agent.py --demo
最后一条用内置合成数据零交互跑完整链，报告落在 report/。不需要配置模型，也不需要联网。

接什么 AI 都行：编排层可插拔

同一套计算内核，三种接法任选，不绑定任何 AI 平台：

  • MCP Server（src/mcp_adapter.py，纯标准库）—— 任何 MCP 客户端可直接接入
  • OpenAI Agents SDK（src/agents_adapter.py）—— 指向任意 OpenAI 兼容端点
  • 本地 CLI / Web UI —— 完全不用大模型也能跑确定性流水线

换前端、换模型都不改口径——因为模型本来就只负责调度与解读，不参与任何计算。

坦诚的局限

这套设计兜得住「算错」，兜不住「想错」：方法论本身对不对（市场对标选哪个来源、带宽幅度定多少），仍然要靠人判断。
目前主要使用者是作者本人，尚无成规模的外部用户——这也是选择开源的原因。
